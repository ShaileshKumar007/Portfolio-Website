An operational view is useful when it helps someone move from a symptom to a next step. Showing more metrics does not automatically make that path clearer.

## Organize around questions

A person opening a health view may need to know:

1. What is affected?
2. Is the signal current?
3. Who owns the next action?
4. What changed recently?

The order matters. A stale green indicator can be less useful than an honest unknown state with a timestamp.

## Preserve context

For each signal, show its source, last-check time, and state. If many services are summarized together, make it possible to understand which underlying item needs attention. Avoid implying that a summary is complete when some sources are unavailable.

## Prefer useful defaults

Start with the issues that need attention and keep healthy detail available without crowding the main view. The goal is to help people notice and investigate, not to create a wall of numbers.

## Questions to validate with users

- Which decisions are made from this view?
- How quickly can a person identify an owner?
- Can the view show stale or missing data distinctly?
- Which details are useful only during investigation?
